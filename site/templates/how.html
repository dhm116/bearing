How it works

Bearing reads the tools your team already uses, writes down what each one says, works out how it all fits together, and answers questions with the sources attached. It does this continuously, on its own.

Bearing

Connect your tools

A connector is a small add-on that knows how to read one tool, such as GitHub or your company directory. You choose which tools to connect.

Connectors only read. They can look at a tool, but never change anything in it, and each one runs sealed off from the rest, reaching only the tool it was given.

  2. Directory · 09:41

  3. GitHub · 09:42

    User pnair is in @payments-team.

  4. GitHub · 09:58

Every note is kept, in order

Write down what each tool says

Each connector reports what its tool says as short notes: this person is in that group, this code needs that team's approval. Bearing keeps every note, with where and when it was seen.

Tools send word the moment something changes, and connectors also re-read everything regularly, so nothing is missed.

Join the dots

Bearing works out which notes are about the same thing. The GitHub user pnair and the directory account priya@acme.example are one person, Priya Nair.

The result is a map of connections, a bit like a subway map: people, teams, code and changes are the stops, and every line between them is a fact that remembers its source. Engineers call this kind of map a graph.

When two tools disagree, Bearing keeps both versions and says so, instead of guessing.

Answer questions, with sources

Ask in a terminal, let your AI coding assistant ask for you, or look it up in a web browser. Everyone gets the same answer from the same map.

Each answer lists the facts behind it, which tool reported them and when, so you can check it for yourself.

It keeps itself up to date

Nobody has to remember to update Bearing. When something changes in one of your tools, Bearing hears about it within seconds and the answer changes with it.

Tools sometimes fail to send word, so Bearing also re-reads them on a schedule and catches anything that slipped through.

  1. 09:00

    Priya moves to the Checkout team in the directory.

  2. 09:00

    The directory tells Bearing.

  3. 09:00

    Ask again, and Priya shows up on Checkout, not Payments.

  4. Regularly

    A full re-read confirms nothing was missed.

Careful by design

  • Read-only

    Connectors look at your tools and never change them.

  • No keys handed out

    Connectors never see the passwords or keys for your tools. Bearing uses them on their behalf.

  • Everything on record

    Every change is written down with who or what made it, and any later tampering shows.

  • Runs where you choose

    You run Bearing yourself, so your data stays with you. It needs no outside AI service.

Going deeper

The specification is the technical description of Bearing, for people who want to build a connector, swap a part or contribute. It uses a few words of its own:

Adapter
A connector.
Observation
One note from a connector about what its tool says.
Subject
A person, team, repository or other thing Bearing keeps a record of.
Fact
A line on the map between two subjects, or a detail about one, with its source.
Graph
The map of all subjects and facts.
