How it works

Adapters read the tools you already run

An adapter has one job: read one system and report what it sees. It is stateless and read-only against its source, and it declares up front which kinds of subject and which predicates it emits, so the core can check everything it sends.

Adapters never decide that two accounts are the same person. That is the core's job, done once with one set of rules for every source.

From M4, adapters run as sandboxed WebAssembly modules that reach the outside world only through capabilities they were granted, and never see the credentials they use.

They report observations

An observation is one source's report about one entity at one moment: its keys, its attributes and its relations, plus evidence a person can check. It travels as a CloudEvent, so any queue can carry it.

Keys stay in the source's own namespace. A snapshot scope says "this is the complete set", which is how a stateless adapter tells the core that something was removed.

The core resolves identity

Every key becomes an alias of a subject, and each subject has an ID Bearing minted that never changes. A renamed repository keeps its subject; a reused name gets a new one.

One matcher scores pairs of the same kind across sources. Teams merge on a good score. People need authoritative evidence or a human's confirmation, and every merge and un-merge is audited and reversible.

…and records facts with their evidence

Everything Bearing knows is a fact: a subject, a predicate and an object. Each fact keeps every source's support separately, with when it was true in the world and when Bearing learned it.

Confidence is the strongest claim within one source system, combined across independent systems, so corroboration counts once per system. A fact is asserted only above its threshold, and conflicting owners are shown as disputed rather than silently resolved.

The graph is the source of truth

Facts live in a graph store. A semantic index sits beside it for fuzzy questions, and every result it returns is checked against the graph. The index can always be rebuilt from the graph; the graph is never rebuilt from the index.

Each component sits behind an interface with a conformance suite. One SurrealDB database serves both the graph and vectors by default, chosen by a store URL, and any backend that passes the suite can replace it.

Every surface asks the same graph

Surfaces hold no logic of their own. Today that is a developer CLI that runs adapters and checks their output. Ownership answers on the command line come next, then the same answers for AI agents through a read-only MCP server.
